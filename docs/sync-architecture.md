# Как устроена синхронизация: от кнопки в игре до строки в таблице

Документ для человека, который хочет понять всю цепочку и проверить её сам, без автора. Кратко: **игра работает у каждого в браузере, а Google-таблица — единственное общее хранилище**. Браузер никогда не обращается к самой таблице. Он обращается к маленькому серверу (скрипту Apps Script), который проверяет запрос и пишет в таблицу.

```
 Браузер игрока ─┐                                   ┌──► листы Overview, Team 1–4 (то, что читаете вы)
 (страница Tilda)│  HTTPS, адрес /exec               │
                 ├─────────────► Code.gs (Apps Script)├──► Decisions, Notes (журнал и заметки)
 Браузер ведущего┘  (data-sync-url)  проверяет, пишет ├──► Players, Settings (кто в игре, состояние)
 (с паролем)                                          └──► Scores (оценки экспертов)
```

Где что лежит в коде:

| Файл | Роль |
| --- | --- |
| `src/sync.mjs` | клиент: собирает события, отправляет, читает ответы |
| `src/storage.mjs` | локальное сохранение игры в браузере и учёт того, что уже подтвердила таблица |
| `src/app.mjs` | вход игрока, опрос состояния, запуск отправки |
| `src/host.mjs` | панель ведущего: игроки, команды, старт, оценки |
| `integrations/google-sheets/Code.gs` | серверная часть (Apps Script) |
| `scripts/fake-google.mjs` | запускает настоящий `Code.gs` на таблице в памяти (для тестов и localhost) |
| `test/sheets.test.mjs`, `test/sync.test.mjs`, `test/hosted.test.mjs` | проверка цепочки целиком |

## 1. Адрес и транспорт

- Адрес веб-приложения (`…/exec`) лежит в атрибуте `data-sync-url` корневого элемента страницы (блок 1). Принимается только `https://…` или `http://localhost…`. Пустой адрес — синхронизации нет, остаётся только Practice.
- **Запись**: `POST` с телом JSON и заголовком `Content-Type: text/plain`. Это сделано намеренно: такой запрос браузер считает «простым» и не отправляет предварительный запрос CORS, который Apps Script не умеет обрабатывать. Скрипт сам разбирает текст как JSON.
- **Чтение**: `GET …/exec?action=…`. Apps Script отвечает редиректом, `fetch` следует ему (`redirect: "follow"`).
- Если браузер не может прочитать ответ (ошибка сети или CORS), игра повторяет запрос в режиме `no-cors`: данные уходят, но подтверждения нет, статус «unconfirmed». Повтор безопасен (см. разд. 4).

## 2. Жизненный цикл игры

Состояние хранится в листе `Settings` (ключ `state`):

| Состояние | Когда | Что можно |
| --- | --- | --- |
| `lobby` | игроки заходят | `join`, `ready`; ведущий `form`, `demo` |
| `formed` | ведущий нажал **Form teams** | то же, плюс поздний игрок попадает в самую малую команду; ведущий `start` |
| `started` | ведущий нажал **Start the game** | игроки пишут решения и заметки; новые игроки не принимаются |

Переходы: `lobby → formed` (`form`), `formed → formed` (повторный `form` перемешивает команды и сбрасывает «ready»), `formed → started` (`start`), любое → `lobby` (`reset`: копия таблицы, затем очистка).

**Внутренний номер игры** (`OMF-…`) нужен коду, но игрокам не показывается. Его создаёт страница ведущего при **Start the game**: он кодирует время старта R1 (минуты в системе по основанию 36), номер перестановки рынков по командам (какая команда получила какой рынок) и случайный хвост. Он записывается в `Settings` (`room`, `start`, `markets`) и возвращается каждому игроку в ответе `me`, когда состояние `started`. По нему строится расписание раундов: `src/rules.mjs` (`makeRoom`, `roomStart`, `marketForTable`, `phaseAt`).

## 3. Кто что может (авторизация)

| Кто | Чем подтверждается | Что может |
| --- | --- | --- |
| Игрок | **секретный пропуск** (случайный `id`, создаётся в браузере при **Join your team**, хранится в localStorage; в таблице только в листе `Players`) | читать и писать **только свою команду**, пока игра идёт |
| Ведущий | **пароль** (свойство скрипта `FACILITATOR_TOKEN`; на странице вводится в панели и хранится в браузере ведущего) | читать список игроков и все команды, формировать команды, стартовать, сбрасывать, отправлять оценки |
| Все остальные | ничего | `ping` и попытка `join` до старта |

Пропуск игрока привязан к команде в `Players`. Каждый запрос на запись проверяется: игрок существует, игра запущена, номер игры в запросе равен текущему, команда в запросе равна его команде. Иначе запись отклоняется (`not your team or game`).

## 4. Путь одного решения (самая важная цепочка)

1. Студент (капитан) нажимает **Lock this choice**. Игра добавляет решение в историю команды (`lockRound` в `src/rules.mjs`) и **сначала сохраняет всё локально**: localStorage, зеркало в IndexedDB и два резервных снимка (`bak1`, `bak2`). Игра не зависит от сети.
2. Сразу после этого запускается `flushSync` (`src/sync.mjs`). Из истории строятся **события**, по одному на каждое зафиксированное решение (`buildEvents`):
   - `id = <номер игры>:<команда>:<номер по порядку>:<цепочка>`: детерминированный, поэтому повторная отправка узнаётся;
   - `chain` — хэш всего, что зафиксировано до этого решения включительно. Если кто-то задним числом перепишет раунд 2, цепочки всех следующих решений изменятся и сервер это заметит;
   - вместе с решением уходят обоснование, компромисс, цена, остаток кредитов, названная проблема (R6), время устройства и разница часов устройства с серверным временем; после R7 к событию добавляется скрытый игровой результат.
3. Из локального хранилища читается, сколько событий таблица уже подтвердила (`readSyncState`: счётчик, хэши заметок, хэш Board Brief — отдельно для каждой команды и адреса). Отправляются только неподтверждённые.
4. Браузер шлёт `POST` `{v:1, participant, sentAt, clockOffsetMs, events:[…]}`.
5. `Code.gs` (`doPost`) берёт глобальную блокировку (одновременные запросы идут по очереди), проверяет пропуск (`allowedTeam`), затем `accept()` проверяет каждое событие: формат номера игры, команда, раунд соответствует порядку, способ фиксации, формат `chain`, `id` соответствует номеру игры и команде. Для каждого события:
   - уже есть такой `id` → `duplicates` (повтор безопасен, ничего не пишется);
   - для этого раунда уже записана другая `chain` → строка пишется с флагом `CONFLICT`;
   - часы устройства и Google расходятся больше чем на 2 минуты → флаг `CLOCK`;
   - все тексты проходят через `text()`: начинающиеся с `=`, `+`, `-`, `@` получают апостроф, чтобы не стать формулой; длина обрезается (1800 символов, Board Brief 5400).
6. Новые строки **добавляются** в `Decisions` (время приёма ставит Google, а не устройство). Затем `refreshTeamViews` пересобирает **лист этой команды** (`Team N`) и её строку в `Overview`: берётся первое зафиксированное решение каждого раунда, к нему подтягиваются заметки.
7. Сервер отвечает `{ok, saved:[id…], duplicates:[id…], rejected:[…]}`. Игра считает подтверждённой **непрерывную начальную часть** событий, записывает счётчик в localStorage. В журнале решений появляется «all N decisions are saved».

**Заметки рабочих листов и Board Brief** отправляются отдельным типом запроса `notes` после того, как все решения подтверждены. Игра хранит хэш последнего отправленного текста каждого поля и шлёт только изменившиеся. У каждого поля свой штамп времени: побеждает более новая версия, старая, пришедшая с опозданием, игнорируется (`ignored`). Пустой текст тоже отправляется, поэтому очистка поля очищает его и в таблице.

**Когда запускается отправка:** сразу после фиксации решения; через 4 секунды после последнего нажатия клавиши в заметке; каждые 30 секунд; когда вкладка уходит в фон; когда появляется сеть; по кнопке **Send again**. Если отправка уже идёт, запрос запоминается и выполняется сразу после неё с самой свежей версией данных.

**Если Google недоступен:** решение лежит локально, в журнале «N decisions waiting to be sent. Retrying automatically.», отправка повторяется каждые 30 секунд. Команда продолжает играть. Когда связь вернётся, уйдут все накопившиеся события одним пакетом (до 20 за запрос).

## 5. Чтение

| Запрос | Кто | Что возвращает |
| --- | --- | --- |
| `?action=ping` | любой | `{"ok":true,"service":"one-market-first","version":3}`: проверка, что скрипт жив |
| `?action=me&id=…` | игрок | состояние игры, его команда, состав команды, капитан, готовность; номер игры и время старта только когда `started` |
| `?action=team&id=…` | игрок | решения, заметки и Board Brief его команды (для продолжения на другом устройстве) |
| `?action=roster&token=…` | ведущий | список игроков с командами, состояние, номер игры (без секретных пропусков) |
| `?action=room&token=…` | ведущий | решения и заметки всех четырёх команд |

Страница игрока опрашивает `me` каждые 5 секунд, пока находится на экране входа (до старта и пока не открыта игра). Панель ведущего опрашивает `roster` и `room` каждые 8 секунд.

**Продолжение на другом устройстве.** Игрок команды нажимает **Play on this device instead**. Скрипт делает его капитаном. Страница запрашивает `team`, из ответа строит запись игры (`recordFromPayload` проверяет её теми же правилами, что и любое сохранение: «подделанные» данные отвергаются) и продолжает с того места, где команда остановилась. Игра сообщает: «Continued from Google Sheets: N of 7 decisions restored».

## 6. Что записывается в каждый лист

| Лист | Кто пишет | Пишется как |
| --- | --- | --- |
| `Decisions` | решения | только добавление |
| `Notes` | заметки, Board Brief | одна строка на поле, обновляется |
| `Team 1–4` | скрипт при каждом решении и заметке | полностью перезаписывается из `Decisions` и `Notes` |
| `Overview` | скрипт | одна строка на команду, обновляется |
| `Players` | `join`, `form`, `ready`, `captain` | строка на игрока |
| `Settings` | `form`, `start`, `reset` | пары «ключ → значение» |
| `Scores` | страница ведущего (`scores`) | перезаписывается целиком |

`Decisions` и `Notes` — первичные данные. `Team N` и `Overview` — производные: их можно в любой момент пересобрать, а если случайно стёрли, они восстановятся при следующем решении или заметке.

## 7. Оценки экспертов

Оценки вводятся только на странице ведущего и хранятся в его браузере (по ключу номера игры). После каждой отметки страница через 4 секунды собирает таблицу (`scoresSheetTable` в `src/presentation.mjs`: рейтинг команд и баллы каждого эксперта по критериям) и отправляет её запросом `scores` с паролем. Лист `Scores` перезаписывается целиком, в конце ставится время обновления.

## 8. Проверка цепочки вручную

Подставьте свой адрес `/exec` и пароль.

```bash
# 1. Скрипт жив?
curl -sL "https://script.google.com/macros/s/ВАШ_АДРЕС/exec?action=ping"
# → {"ok":true,"service":"one-market-first","version":3}

# 2. Ведущий видит игроков? (пароль в адресе: делайте это только у себя в терминале)
curl -sL "https://script.google.com/macros/s/ВАШ_АДРЕС/exec?action=roster&token=ВАШ_ПАРОЛЬ"
# → {"ok":true,"state":"lobby","room":"","start":"","players":[]}

# 3. Неверный пароль
curl -sL "https://script.google.com/macros/s/ВАШ_АДРЕС/exec?action=roster&token=nope"
# → {"ok":false,"error":"Wrong facilitator password."}
```

Если шаг 1 возвращает страницу входа Google, развёртывание создано с доступом не «Anyone». Если `{"ok":false,"error":"Unknown action."}`, вы вставили старый `Code.gs`: нужна новая версия развёртывания.

Те же запросы без Google (на локальной имитации): запустите `npm start` и подставьте `http://localhost:8080/sheets` вместо адреса `/exec`.

## 9. Автоматические тесты цепочки

Запуск: `npm test` (браузерные тесты запускаются, если установлен Playwright: `npm i --no-save playwright && npx playwright install chromium`).

- `test/sheets.test.mjs` — настоящий `Code.gs` на таблице в памяти: вход игроков, случайное распределение (размер команд, равномерность иностранных студентов), права доступа, дубликаты, конфликты, листы команд, `Scores`, новая игра.
- `test/sync.test.mjs` — клиент: повтор отправки, подтверждённая часть, заметки, недоступная таблица, права.
- `test/hosted.test.mjs` — настоящий браузер и настоящий HTTP: вход игрока, команды, старт, решения и заметки доходят до листов, продолжение на другом устройстве, панель ведущего, отправка оценок, новая игра, обрыв связи.

**Чего тесты не проверяют:** реальные Google Sheets, квоты Google, свойства Tilda. Для этого есть ручная проверка из [tilda-setup.md](tilda-setup.md) (часть D).

## 10. Типовые сбои и что видно

| Что произошло | Что видит игрок / ведущий | Что делать |
| --- | --- | --- |
| Нет интернета | «N decisions waiting to be sent. Retrying automatically.» | ничего: данные досылаются сами; можно нажать **Send again** |
| Адрес не тот или доступ не «Anyone» | то же, плюс текст ошибки в скобках | проверить адрес в блоке 1 и развёртывание |
| Закрыли вкладку, не успев отправить | при следующем открытии игра досылает неподтверждённое | открыть страницу на том же устройстве |
| Устройство капитана сломалось | — | любой игрок команды: **Play on this device instead** |
| Данные браузера очищены | экран входа, имя занято | другой игрок команды берёт управление; либо ведущий начинает новую игру |
| Кто-то правил листы `Team N` или `Overview` вручную | правки пропадут при следующей записи: эти листы пересобираются | правьте только копию; первичные данные в `Decisions` и `Notes` |
| В журнале пометка `CONFLICT` | первая запись остаётся главной; число лишних записей в колонке Flags | смотрите все записи в `Decisions` |
| В журнале пометка `CLOCK` | время по часам устройства могло быть неверным | сверьте часы устройства |
